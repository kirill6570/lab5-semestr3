# Лабораторная работа №5 — вариант 10

Короткевич Кирилл Олегович, АБ-522. Генерация HTML-отчётов с паттерном «Строитель».

## Visual Studio Code на Ubuntu

Откройте папку «Лаба№5». В меню «Терминал → Создать терминал» выполните:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -Iinclude main.cpp src/*.cpp -o lab5
./lab5
```

Ctrl+Shift+B собирает программу через подготовленную задачу VS Code. Для F5 нужны расширение Microsoft C/C++ и GDB. Запуск из терминала от них не зависит.

Выберите дисциплину, номер работы, тему, цель, задание, вывод и путь к скриншоту PNG/JPG. Автор и группа заданы в main.cpp. Путь вводите без кавычек; пустая строка означает отчёт без скриншота.

Каждый ручной отчёт сохраняется отдельно: например, `generated/discipline-1-report-001/report.html`, затем `discipline-1-report-002/report.html`. Программа печатает готовую ссылку `file:///…/report.html`. Старые отчёты не перезаписываются. Папку `assets` храните рядом с HTML.

## Три демонстрационных документа

```bash
./lab5 --demo
```

Каждый запуск получает отдельную папку `generated/demo-001`, `demo-002` и далее. Внутри — `discipline-1`, `discipline-2`, `discipline-3`, у каждой свой `report.html`. Темы, цели, задания и выводы трёх примеров различаются. Это демонстрация генератора для трёх дисциплин, а не три выполненные лабораторные. Пример изображения — реальный снимок сформированного HTML. Его можно заменить в `assets/demo-preview.png`.

`./lab5 --demo my-reports` задаёт другой каталог. Запускайте программу из папки проекта: main.cpp, include, src и assets/uml.svg читаются по относительным путям. Для листинга HTML программа читает все исходные файлы проекта.

## Структура паттерна

Report — продукт; ReportBuilder — абстрактный строитель; HtmlReportBuilder — конкретный строитель; Director — порядок сборки; LabData — данные. Директор работает через ссылку на абстрактный класс. Один HTML-строитель обслуживает три дисциплины, поскольку формат одинаков, меняются только данные.

Собираются титульный блок, цель, задание, UML, раскрываемый листинг, таблица, диаграмма, скриншот и вывод. В Word-отчёт по лабораторной код не включается по просьбе автора; ссылка на GitHub размещена в конце отчёта.

## Проверки

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
python3 tests/test_cli.py
```

Проверяются экранирование HTML, повторная сборка, независимость продукта, три дисциплины, наличие ресурсов, некорректный ввод и ошибки файлов. Тест CLI работает во временной папке и проверяет также разные ссылки и сохранность предыдущих отчётов.

Внешние библиотеки программе не нужны: используется стандартная библиотека C++17.

## Файлы проекта

- `main.cpp` — меню, заполнение данных и запуск генерации.
- `include/LabData.h` — данные отчёта.
- `include/Report.h`, `src/Report.cpp` — продукт: готовый документ.
- `include/ReportBuilder.h` — интерфейс абстрактного строителя.
- `include/HtmlReportBuilder.h`, `src/HtmlReportBuilder.cpp` — сборка HTML-разделов.
- `include/Director.h`, `src/Director.cpp` — порядок шагов сборки.
- `include/ReportGenerator.h`, `src/ReportGenerator.cpp` — генерация файлов и диаграммы.
- `include/ConsoleInput.h`, `src/ConsoleInput.cpp` — ввод с повторным запросом при ошибках.
- `include/FileUtils.h`, `src/FileUtils.cpp` — работа с файлами, датой, ссылками и экранированием HTML.

Объявления находятся в `.h`, реализации — в `.cpp`. CMake собирает общую библиотеку `report_core`, которую используют программа и тесты. В VS Code задача Ctrl+Shift+B также собирает все модули.
